## 1. Идея

Однопользовательская игра-менеджер: игрок — генеральный менеджер и тренер клуба НХЛ. Он собирает состав, ставит звенья и вратарей, проводит обмены и драфт, ведёт клуб сезон за сезоном и смотрит матчи в 3Д.

Главное отличие от Eastside и Franchise Hockey Manager — **честный движок матча**. Он построен на модели прогнозов NHL-STATS.RU, проверенной на ~9800 реальных матчах, а не на придуманных формулах. Рейтинги игроков выводятся из настоящей статистики: xG, игровое время, сейвы сверх ожидаемого, трекинг НХЛ EDGE. Второй козырь — **«Машина времени»**: любой сезон НХЛ с 2008 года с реальными составами.

**[1.1]** Третий козырь — **3Д-трансляция, которая не врёт**. Каждый бросок на экране — это бросок из движка событий: с той же точки, того же типа и с тем же xG, что разыграл движок. Модель решает, 3Д показывает.

## 2. Платформа и технологии **[1.1]**

- **Godot 4.7 + C#.** Почему не Unity (на нём сделан FM26):
  - всё в Godot — сцены, материалы, анимации — хранится текстом, поэтому Claude может писать и править всё, а не только скрипты;
  - Godot можно собрать и запустить в рабочем окружении Claude без экрана, прогнать тесты и снять кадры 3Д-сцены для проверки. Это уже проверено: C#-проект собирается, Forward+ рендерит;
  - бесплатно, без отчислений и аккаунтов, экспорт под Windows и macOS из коробки.
  
  Потолок графики Forward+ (глобальное освещение, отражения на льду, объёмный свет, свечение) для стилизованного FM-уровня с запасом.
- **Ядро симуляции** — отдельная C#-библиотека без зависимости от Godot. Её можно тестировать и гонять тысячами сезонов.
- **Данные — сжатый JSON вместо SQLite** (отход от 1.0). Причины: ноль внешних библиотек (SQLite в C# требует нативных пакетов и ломает сборку под разные платформы), файл легко подменить модом, объём небольшой — несколько мегабайт. Сохранения карьеры — тоже сжатый JSON.
- **Целевая производительность:** 60 кадров в секунду на MacBook Pro M5 и на ПК с RTX 4070 в 1440p; в 4K — с масштабированием (FSR/MetalFX).

## 4. Ключевые механики

### 4.1. Состав и звенья
- 4 тройки нападения, 3 пары защиты, 2 вратаря, 2 звена большинства и 2 меньшинства.
- Игровое время по звеньям настраивается (первые звенья 18–22 минуты, четвёртое 8–11).
- Усталость: внутри матча (длинные смены, большинство) и календарная (второй матч за два дня: −5% к голам уставшей команды, как в модели).

### 4.2. Рейтинги игроков
Шкала 1–99 (перцентиль среди игроков позиции), выводится из статистики детерминированно и **не правится вручную**. Для молодых — скрытый потенциал (генерируется).

### 4.3. Обмены и ИИ-генменеджеры
- Ценность игрока = вклад в ожидаемые голы команды за остаток контракта с поправкой на возраст.
- ИИ-клубы оценивают сделки по той же шкале, плюс потребности (позиция, кэп) и «характер» клуба (перестройка / борьба за Кубок).

### 4.4. Экономика
- **MVP — без потолка зарплат**, лимит заявки — 23 игрока.
- Далее — упрощённые контракты: зарплата по рейтингу и возрасту (генерируется), потолок по правилам НХЛ.

### 4.5. Развитие и старение
Кривые возраста по многосезонной статистике (пик обычно 25–28 лет), плюс случайность и потенциал молодых.

### 4.6. Драфт
Проспекты генерируются: имя, позиция, потенциал, страна.

## 6. Рейтинги игроков — как считать

Все показатели — за 60 минут игры, со сжатием к среднему по позиции (байесовское усреднение с весом ~20 матчей, как в модели).

| Характеристика | Из чего |
|---|---|
| Атака (создание моментов) | Личный xG за 60 минут |
| Реализация | Голы / личный xG, сильно сжатая к 1,0 |
| Пас | Первые передачи за 60 минут |
| Оборона | xG соперника при игроке на льду за 60 минут против среднего по команде |
| Владение | Доля попыток бросков при игроке на льду (5×5) |
| Скорость, бросок | НХЛ EDGE (текущий сезон; для исторических — из корреляций или по умолчанию) |
| Выносливость | Среднее игровое время |
| Вратарь | Сейвы сверх ожидаемого на единицу xG против, 3 сезона с весами 1 / 0,8 / 0,64, сильно сжатые к нулю |

В движке — исходные числа; шкала 1–99 — только для интерфейса. **[1.1]** Скорость и бросок из EDGE дополнительно управляют 3Д: скоростью катания модели и скоростью шайбы на броске.

## 7. Движок матча

Три слоя. Каждый следующий в среднем совпадает с предыдущим и ничего не решает сам.

```
Уровень 1 «матч целиком»  →  Уровень 2 «матч по событиям»  →  Постановщик 3Д
   (λ, Пуассон, ОТ)            (смены, броски, сейвы, удаления)    (траектории, анимации, камера)
   решает силу                 решает, ЧТО произошло                решает, КАК это выглядит
```

### 7.1. Уровень 1 — «матч целиком» (MVP)
Почти один в один модель `scripts/model.py`, версия 4.4:
1. λ = средний уровень лиги × атака × оборона соперника × домашнее преимущество. Атака и оборона — из рейтингов **поставленных на матч звеньев**, взвешенных по игровому времени.
2. Поправки: вратарь (множитель 0,9–1,1), второй матч за два дня (×0,95 / ÷0,95), травмы — через состав.
3. Счёт основного времени — Пуассон с повышенной долей ничьих (`TIE_K = 1.35`).
4. Ничья → ОТ 3×3: хозяева 51,7% + поправка на силу (`OT_HOME = 0.517`, `OT_K = 0.45`); затем буллиты, почти монетка.

Используется для всех матчей лиги, кроме матчей клуба игрока, и для быстрой симуляции: тысячи сезонов в минуту.

### 7.2. Уровень 2 — «матч по событиям»
Матч делится на тики по 1 секунде (**[1.1]** было 5: для 3Д нужна точная временная шкала), на льду — конкретные звенья по сменам.
- **Владение и вход в зону:** кто владеет, где шайба (зона защиты / средняя / атаки), вход с ходу или вброс.
- **Попытки бросков:** частота — от владения звеньев на льду (Корси), плюс эффекты счёта.
- **Качество броска:** точка (x, y), тип (кистевой, щелчок, с хода, добивание, подправление) — из реальных распределений бросков MoneyPuck; у каждого броска свой xG.
- **Бросающий** — среди игроков на льду пропорционально личному xG; **ассистенты** — пропорционально рейтингу паса.
- **Исход броска:** гол / сейв с фиксацией / сейв с отскоком / мимо / заблокирован. Вероятность гола = xG × реализация бросающего × множитель вратаря.
- **Удаления → большинство**, снятие вратаря в концовке, ОТ 3×3, буллиты по отдельной модели.
- Тексты для текстовой трансляции: «Капризов, бросок с хода из слота — сейв».

**[1.1] Выход уровня 2 — «сценарий матча»:** список событий со временем, участниками, точками на площадке и исходами. Он сохраняется, по нему строятся 3Д, протокол, статистика и повторы.

**Калибровка:** на тысячах симуляций совпадают с реальностью голы (~6,2 за матч), броски в створ (~29 на команду), реализация большинства (~20%), доля ОТ (~22%), доля побед хозяев.

### 7.3. Критерии готовности движка (обязательные тесты, запускаются в CI)
1. **Средние лиги:** голы, броски, ОТ, большинство — в пределах ±3% от реальных.
2. **Исторический сезон** (например, 2023-24) с реальными составами, 100 прогонов: корреляция очков клубов с реальной таблицей ≥ 0,7.
3. **Калибровка:** при фаворите 70% тот выигрывает 68–72% симуляций. Эталон — таблица калибровки модели на 9781 матче 2018–2025.
4. **Чувствительность:** слабый вратарь вместо основного заметно ухудшает результаты, но не катастрофически (±10% к пропущенным).
5. **[1.1] Совпадение уровней:** на 10 000 матчей уровень 2 даёт те же шансы, что уровень 1, с точностью ±1,5 п.п.

### 7.4. Постановщик 3Д **[1.1]**

Получает сценарий матча и превращает его в движение 12 игроков и шайбы. Правило одно: **3Д не может противоречить сценарию.** Если в сценарии сейв после щелчка с синей линии, на экране щелчок именно с синей линии и именно сейв.

**Как строится движение:**
- **Тактические шаблоны** под каждую ситуацию: выход из зоны, средняя зона, атака с ходу, позиционная атака, большинство (1-3-1, «зонтик»), меньшинство («коробка», «ромб»), вбрасывание, снятие вратаря. Шаблон задаёт целевые точки каждого игрока относительно шайбы.
- **Ключевые кадры из сценария:** «в 12:41 бросок с точки (x, y)» — значит, к этому моменту бросающий должен быть в этой точке, а шайба — у него на крюке. Постановщик планирует пасы и проходы так, чтобы прийти туда вовремя.
- **Движение игроков** — модель катания: разгон, торможение, повороты с ограничением радиуса, скорость из EDGE. Никаких телепортаций и скольжения боком.
- **Шайба** летит по баллистике между ключевыми кадрами: пас по льду, бросок, отскок от вратаря или борта.
- **Смены** — игроки реально едут к скамейке и выходят из неё.

**Анимации игроков:** катание (шаг, накат, перебежка, торможение, разворот), кистевой бросок, щелчок, пас, приём, силовой приём, борьба у борта, падение; у вратаря — стойка, баттерфляй, ловушка, блин, перемещение по площади; празднование гола, рукопожатие. Анимации катания — процедурные (ноги по IK под фактическую скорость), чтобы не было «лунной походки». Остальное — ключевые анимации, смешиваемые по ситуации.

**Камеры:** трансляционная (сбоку, сверху трибун, ведёт шайбу), тактическая (сверху), из-за ворот, повтор гола с 2–3 ракурсов в замедлении.

**Арена и лёд:** площадка строится кодом по точным размерам НХЛ (61 × 26 м, радиус углов 8,5 м, все линии, круги и зоны вратаря); лёд с отражениями и следами коньков, борта с рекламой (вымышленной), стекло, ворота с сеткой, трибуны с болельщиками в цветах клуба (инстансы, тысячи фигур без потери кадров), табло со счётом, звук: стадион, удары, сирена гола.

**Внешний вид игроков:** форма в цветах клуба, номер и фамилия на спине, эмблема на груди, шлем, краги, клюшка; рост и вес — из данных (Овечкин крупнее Хьюза). Лица — обобщённые (реальные лица не воспроизводим).

**Ассеты — путь к качеству:**
1. **Этап 4а (первая 3Д-версия):** площадка, арена, камеры, стилизованные фигуры игроков из кода, вся постановка. Это проверка, что движение выглядит как хоккей.
2. **Этап 4б:** анимированная модель хоккеиста в экипировке. Источники по приоритету: бесплатные модели с открытой лицензией (CC0) и Mixamo для базовых движений, дорабатываемые под хоккей; хоккейный пак анимаций на маркетплейсе, если найдётся подходящий по лицензии (решение и покупка — за заказчиком); генерация экипировки нейросетями для 3Д (Meshy, Tripo).
3. **Этап 7:** полировка: освещение арены, частицы льда, болельщики, интро матча.

**Эталон качества** — 3Д-движок FM26: читаемая тактика, правдоподобное движение, трансляционная подача. Уровень EA NHL (захват движений, реальные лица) — вне рамок проекта.

## 8. Архитектура и репозиторий **[1.1]**

```
    AI/                 ИИ-генменеджеры

  game/                 проект Godot 4.7
    UI/                 клуб, состав и звенья, календарь, таблица, обмены, драфт
    Match3D/            постановщик, площадка, арена, игроки, камеры, повторы

  .github/workflows/

    build.yml           экспорт Windows (.exe) и macOS (.app, универсальный) → релиз
```

**Как работаем:** Claude пишет код, собирает и проверяет ядро и 3Д-сцены у себя (включая снимки кадров), пушит в репозиторий. GitHub Actions собирает данные и готовые сборки под Windows и macOS. Заказчик скачивает сборку из релиза, играет и пишет, что не так.

Про macOS: сборка не подписана сертификатом Apple, поэтому первый запуск — правый клик → «Открыть» (или одна команда в терминале). Для некоммерческого проекта это нормально.

## 10. Права и лицензии **[1.1]**

Проект **бесплатный и некоммерческий** — это снимает главные вопросы, но обязательства остаются:
- **MoneyPuck:** данные только для некоммерческого использования, **обязательно указать источник** — в меню «Об игре» и в README.
- **НХЛ, клубы, эмблемы, игроки** — товарные знаки лиги и права NHLPA. Фанатские бесплатные проекты обычно терпят, но риск требования убрать остаётся. Поэтому имена, эмблемы и цвета лежат **отдельным файлом данных**: при необходимости их можно заменить, не трогая игру. Эмблемы в репозиторий не коммитятся — они скачиваются при сборке данных.
- В игре — заметная строка: «Неофициальная фанатская игра, не связана с НХЛ и NHLPA».
- Лица игроков не воспроизводятся; реклама на бортах — вымышленная.
- Монетизация (донаты, платная версия) потребует пересмотра раздела: см. версию 1.0, вариант «вымышленная лига».
