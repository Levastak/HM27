# Заметки для разработки HM27

Игру целиком пишет Claude; заказчик — Лев Кузьминых, тестирует сборки на Mac (M5) и ПК (RTX 4070). Весь текст для игрока — по-русски; имена игроков и названия клубов по умолчанию по-английски, как в НХЛ (настройка в меню, `Names.English`). ТЗ — `docs/concept.md`. Замечания после тестов и план — `docs/backlog.md`.

## Структура
- `core/HM27.Core` — ядро на C# (.NET 8) без Godot и без NuGet-пакетов. Движок уровня 1 (`MatchEngine.cs`) повторяет `scripts/model.py` v4.4 из Levastak/nhl-svodka; константы там же с комментариями.
- `core/HM27.Check` — консольная проверка критериев ТЗ 7.3; запускается в CI. Любая правка движка должна её проходить:
  `dotnet run -c Release --project core/HM27.Check -- game/data/hm27-data.json 10`
- `game/` — проект Godot 4.7.2 .NET. Интерфейс строится кодом (`game/ui/*.cs`), без .tscn-сцен, кроме корневых.
- `data/build.py` — база `game/data/hm27-data.json` из файлов nhl-svodka (`site/data.json`, `site/names_ru.json`, `scripts/prior.json`).
- Модель игрока (ТЗ — документ «HM27 — модель игрока»): `data/fetch_pbp.py` (workflow «Сырые данные» → релиз raw-data: протоколы, смены, страницы игроков, EDGE) →
  `data/derive.py` (xG, RAPM, характеристики 1–20 с погрешностью → `data/derived.json.gz`, ревью `data/review.py`, ручные поправки `data/overrides.json`) →
  `data/history.py` (возрастные кривые по сводкам MoneyPuck 2010–2026 → `data/age_curves.json`) →
  `data/merge_model.py` (в базу игры, формат 3; капитаны — `data/leaders.json`; номинации на Мастертон/Кинг Клэнси — `data/character.json`;
  тёзки в одном клубе — `overrides.json` → namesakes; темпы за 5 сезонов для раздачи голов/передач — ixg60/fin/apg; реальный сезон 2025-26 — `real` для сверки). Ассеты релиза качать через REST: `gh api -H "Accept: application/octet-stream" repos/Levastak/HM27/releases/assets/<id>`.
- Роли считаются в ядре из характеристик (`Roles` в `PlayerModel.cs`); проверка «роли без противоречий» в HM27.Check.
- В ядре: `PlayerModel.cs` — истинные значения (разыгрываются от сида вокруг данных), видимые (знание клуба), КА/ПА 1–200, характер; `Development` — раз в неделю.
  ПА — потолок, а не прогноз: рост зависит от условий (характер, минуты и роль, удача сезона, оценки, травмы); до ПА доходят ~25% (проверка в HM27.Check).
  Движок учитывает сдвиг «истинный уровень − данные + форма» (LVL_K, G_LVL, D_LVL); база калибровки считается после розыгрыша, но без формы (`DlBase`), поэтому состав по умолчанию = сила модели, а форма меняет результат.
  Характер: сильные метки на старте только из фактов (`data/character.json`: капитанство, награды и номинации за характер, серии без пропусков, скидки и просьбы об обмене; `data/leaders.json`), случайная часть ограничена; дальше характер меняется с карьерой (`Development.Character`). Особенности стиля и Х-фактор — `Traits.cs`, считаются в derive.py; они подтверждают роли (`Roles.TraitFit`).
  Вратари: талант разыгрывается с половиной погрешности данных (G_DRAW), зато каждый сезон — «форма сезона» (G_SEASON): по MoneyPuck сезон вратаря наполовину талант, наполовину сезонная удача, серий почти нет (G_FORM).

## Движок матча
- Новые карьеры: движок по сменам (`ShiftEngine.cs`): посекундно, звенья и пары по минутам тренера, спецбригады, усталость, 5×5/большинство/4×4/снятый вратарь/ОТ 3×3, броски (кто, зона, блок, мимо, створ, добивание), удаления, буллиты. Протокол игроков — `MatchResult.Box` (хранится только для своих матчей, в сезонную статистику идёт всегда).
  Калибровка та же, что у силы «снизу вверх»: интенсивность голов в момент = база состава (цели НХЛ) × e^(атака пятёрки + оборона пятёрки соперника); спецзвенья — против среднего звена своего вида (`Refs`), контраст звеньев внутри клуба — `LINE_K`.
  Цели — `data/engine_targets.py` → `data/engine_targets.json` (протоколы и карты смен НХЛ 2022-26). Сверка: `dotnet run -c Release --project core/HM27.Check -- game/data/hm27-data.json engine 3`.
- Особенности и навыки броска — по протоколам: `data/trait_targets.py` → `data/trait_targets.json` (подписи особенностей и регрессия реализации по зонам).
  Проверки «Особенности в игре» и «Реализация по зонам»: те же показатели на матчах игры. Х-фактор сверх шкалы не даёт ничего (НХЛ: ×0,98) — бонуса нет;
  дальний бросок — отдельный навык бросков издали (`LNG_FAR`), завершение у верха шкалы смягчено (`FIN_TOP`).
- Вбрасывания (`FO_K`, окно 30 с после вбрасывания по зонам — `FO_MULT`), силовые/отборы/потери по характеристикам — по протоколам НХЛ; часть силы пятёрки идёт в качество бросков (`QS_A`, `QS_D`), иначе % отражённых почти не зависит от обороны и вратаря.
- Чужое место в звене — `Lineup.SlotPenalty` (вбрасывания крайних по данным, остальное — дизайн); неполные звенья в источнике добираются по КА (`Lineup.Fill`, `SwapInStronger`).
- Сыгранность (этап «Тренер»): `Career.Chem` — минуты вместе для пар партнёров (тройка между собой, пара защиты между собой), движок отдаёт `MatchResult.PairSec` после матча.
  Сыгранность пары = 1 − e^(−(40 + минуты)/200); звенья и спецбригады на старте — 75% (`FAM_REF`, нейтрально). Эффект на атаку пятёрки и оборону против неё — `ShiftEngine.FAM_MAX` (новое звено ≈ −2%, сыгранное ≈ +0,8%); при снятом вратаре не учитывается. Проверка «Сыгранность» в HM27.Check.
- Травмы — `Injuries.cs`: ~18–19 на клуб за сезон, ~180 игроко-матчей. Свой клуб: место выбывшего запоминается (`Lineup.Hold`), после лазарета помощник возвращает его туда (`Lineup.Restore`), спецбригады латаются по одному месту; травмированные на старте — на место в составе здорового клуба. Основному вратарю отдых при свежести ниже 60%.
- Учётный xG (`ShiftEngine.XG_CAL`) — только для статистики: сумма «сейвов сверх ожидаемых» по лиге ≈ 0.
- Логотипы и лица — вшитый пак `game/art/art.pak` (`tools/fetch_art.py`, ~78 МБ: 32 эмблемы в двух версиях и фото всех игроков базы): в GitHub Actions его скачивает цель `FetchArt` в `HM27.csproj` перед каждой сборкой (в репозиторий не кладётся — `.gitignore`). Локально для снимков: достать из `HM27.pck` релиза dev (поиск `HM27ART1`, длина — 12 + индекс + данные). Только для личного пользования; публичный релиз — как в FM (свои картинки и пользовательские паки).
- Сохранение сжато gzip (`Main.Save`/`ReadSave`, старые несжатые читаются); JSON без экранирования кириллицы. Проверка травм: `... HM27.Check -- game/data/hm27-data.json injuries`.
- Сохранения — слоты `user://saves/<slot>.hm27` + `<slot>.meta.json` (`Main.SaveMeta`: название, клуб, дата в игре, счёт, время): `Main.NewCareer(team, name)`, `Save`, `SaveAs`, `LoadSlot`, `RenameSlot`, `DeleteSlot`; экран «Карьеры» — `SavesScreen` (`--screen=saves`); старый `user://career.json` переносится сам (`Migrate`).
- Нагрузка за сезон — `Fatigue.cs` (свежесть 0–100, нормы НХЛ: нап. 23, защ. 27 мин, вратарь ~65 матчей); травмы зависят от минут и усталости. Видимая форма — `PlayerForm.cs`; сила скрытой формы `FORM_U` проверена «Серии игроков».
- Звёзды КА/ПА — `StarScale.cs`: по умолчанию относительно своего клуба (как в FM), переключатель в меню; класс словами по месту в лиге.
- Шкала характеристик на экране — `Ds.Show/ShowI` (общая для хоккея: худший в НХЛ ≈ 6, средний ≈ 13, лучшие 18–20); данные и движок — в прежней шкале НХЛ, переводить только при показе. Малая выборка (мощь, скорость у новичков) — `merge_model.small_sample`: сжатие к позиции и уровню по числу матчей, исходник в `fx.edge_raw`.
- Развитие: ~30% годового изменения по ходу сезона (`Development.Week`), ~70% летом (`Development.Offseason`, вызывать при смене сезона). Розыгрыш на старте обрезан на ±1,5 погрешности; потолок молодых с малой выборкой — с учётом номера драфта (`PlayerModel.Pedigree`).
- Старые сохранения (сила модели) — движок «матч целиком» (`MatchEngine.Play`). Прогноз до матча (`MatchEngine.Odds`) общий; для движка по сменам — `ShiftEngine.SHARP`.

## Игровой цикл (этап 1)
- Планы: другие лиги со временем тоже станут играбельными (не завязываться на НХЛ там, где можно); пока — полируем НХЛ, без АХЛ. Финансы — только потолок зарплат и бюджет персонала; позже — уровни базы и арены, настроение болельщиков.
- «Продолжить» — один день (`Shell.OnContinue`), «До матча» — `Career.SimToUserGame(stopOnDecision: true)`; лента 7 дней в полосе клуба.
- Решения — письма с вариантами (`Message.Options/Choice/Required/Due/Action/Target/Reply`, ядро `Decisions.cs`): обязательные не пускают «Продолжить»; после срока — вариант по умолчанию (так же в HM27.Check). Сейчас: «мало играю» (обещание сверяется по фактам через 14 дней — `Career.Promises`), «сыграю через боль» (`PlayerState.HurtUntil`: −0,7 к уровню, риск травмы ×2,5).
- Настрой — `Morale.cs`: роль и минуты против ожидания по статусу, результаты, оценки, решения; тянется к норме характера; эффект `MOR_K` от среднего по лиги (нейтрально). Страница «Раздевалка» (`RoomPage`). Проверка «Настрой и решения»; «Раннее снятие» мерится с выключенным настроем (иначе шум).
- Прогноз до матча для движка по сменам — `ShiftEngine.SHARP` 1,15 (подбор по «Калибровке»).
- Помощник тренера — `Coach.cs` (этап «Тренер», принцип «нет одного верного решения»): план на матч `Coach.Prepare` через `Career.Sides(g)` (и в прогнозе, и в матче) — `MatchSide.Tempo`, `Pull1/Pull2`.
  Темп по сопернику (`Lineup.TempoAuto`): какой из трёх даёт больше очков по прогнозу. Снятие вратаря (`Lineup.Pull`: 0 как в НХЛ за 2:00, 1 рано 4:00/5:00, 2 по расчёту) — цепь по секундам с частотами НХЛ 6×5/в пустые и λ матча (оптимум 4–6 мин при −1, как у Asness & Brown; потолок 7:00/9:00). Разгром (3+) бьёт по настрою.
  Система игры — `Tactics.cs` (страница «Тактика», `TacticsPage` с доской `TacticsBoard`): 9 рычагов, полюса −1/0/+1 в `Lineup.Sys`, выучка `Lineup.Learn`. Порядок в массиве исторический (первые 4 — fc, en, da, sh — из старых сохранений; потом agg, dz, bo, pp, pk), для экрана — фазы `Tactics.Phases` (без шайбы / с шайбой / спецбригады), готовые стили `Tactics.Styles`.
  Пригодность — стиль, а не класс (нужные характеристики минус средняя игрока), в SD клубов лиги (у большинства и меньшинства — по их звеньям, `FIT_S`); эффект = база края (размен) + FIT × пригодность + контрприёмы соперника − невыученность. Подпись края — `Tactics.Knobs` (силовые, отборы, потери, потери соперника, блоки, броски соперника у ворот/издали, вбрасывания в своей зоне, атаки с хода; в большинстве/меньшинстве — свои множители): движок держит голы по силе (`Effect.EngF/EngA`), подпись меняет состав событий. Удаления и спецбригады в прогнозе — по доле голов в большинстве (`PP_SHARE`, `Effect.SpF/SpA`), движок их разыгрывает сам.
  Нормировка по лиге `Tactics.Norm` (кэш по дню и системам): системы перераспределяют голы, удаления, броски между клубами, а не меняют их в лиге. ИИ на старте — система под состав (`Tactics.Init/Suggest`). Сверка движка с моделью: `... tactics N`; подписи схем: проверка «Подписи схем», подробно `... signs N`.
  Атака с хода (`ShiftEngine.RUSH_*`): после отбора или потери соперника 10 с голы ×2 (длинный пас — сильнее), вне окна — нормировка; события с хода — `MatchEvent.R`. Счётчики движка по сторонам — `MatchResult.HomeStats/AwayStats` (не сохраняются) → журнал тренера `Journal.cs` (`Career.Journal`, страница «Что сработало» — `JournalPage`): только факты, система на старте матча (`MatchSide.StartSys`).
  Цифр выгоды решений игрок не видит: советы помощника и скаута — словами (`Staff.GainWord/GainVs/ConfWord`), цифры — только факты (свежесть, сыгранность, статистика, шанс отыграться при снятии вратаря).
  Роли звеньев (`Lineup.FRole/DRole`: 0 обычная, 1 атакующая, 2 оборонительная; `Matchup`): движок на каждой остановке (`ShiftEngine.Deploy`: гости, потом хозяева — последняя смена) выпускает атакующее звено на вбрасывание в зоне атаки, оборонительное — в своей и против лучшей тройки соперника (дома — на остановках, на ходу — оба); готовность `DEPLOY_E`, `DEPLOY_OVER`. Роли по умолчанию — `Tactics.DefaultRoles`. Проверка «Роли звеньев», подробно `... roles N`.
  Матч по шагам: `ShiftEngine.Start` → `Sim` (`RunTo`, `Apply` перечитывает стороны без трат случайности, `OnBreak` — перерывы); проверка «Матч по шагам» (`... steps`). План на матч — `Career.Plan` (`MatchPlan`: система на матч `MatchSide.Plan`, задания на соперника `Targets` — до трёх: опека, давить, жёстко, не давать бросать; `Targeting`), скаут — `Scout.For` (советы заданий — `Report.Tips`), экран «до матча» в `MatchScreen.ShowPreview` (концовка: темп и снятие вратаря на матч). Тренеры ИИ против клуба игрока опекают его лучшего нападающего (гибкие; в плей-офф — почти все).
  Правила в перерывах — `Rules` в Coach.cs (`Lineup.Rules`; свой клуб — `Rules.Default`, ИИ — только смена вратаря: поведение при счёте уже в эффекте счёта НХЛ); страница «Правила матча» (`RulesPage`). Смена вратаря — `Sim.SwapGoalie`, сменщик в `MatchResult.HomeGoalie2/AwayGoalie2`, решение — ему.
  Указания игрокам — `Orders.cs` (`Lineup.Orders`, накладываются в `Sim.Apply`): размен с пригодностью (нужные характеристики минус средняя игрока), не по душе (< −0,5) — минус настрой после матча; выбор — в «Звеньях» над кандидатами. Проверка «Указания игрокам», подробно `... orders N`.
  Трансляция своего матча — `Career.BeginLive/FinishLive` (`LiveGame`: Sim с `PauseAtBreaks`, свой состав — копия, ИИ решает в перерыве сам), экран — `MatchScreen.ProcessLive`: часы ×1 = 20 игровых секунд в секунду. Пауза в любой момент и перерыв открывают панель тренера (`FillCoach`): советы `LiveAdvice.For` (правила, контрприёмы, «не идёт игра», давить на того, кто теряет шайбу, тайм-аут), указания с бровки `Shouts` (быстрые смены системы; слова команде — раз за период, эффект `MatchSide.Spark` по настроению раздевалки), звенья (`Sim.SwapLines`, минуты `Sim.SetMinutes`, «три тройки»), состояние (свежесть, время, +/−, настрой), тактика целиком, задания. Тайм-аут — `Sim.Timeout` (один, свежесть +25%), видеопросмотр гола соперника — `Sim.Challenge` (за ~9% голов нарушение, детерминированно; неудача — удаление), мнение видеотренера — `Shouts.VideoRead`. «Сразу к итогу» — помощник доигрывает по правилам. После матча — «Разбор» (`MatchScreen.Review`).
  Доверие к тренеру — `Trust.cs` (`PlayerState.Trust`, только свой клуб): обещания, разговоры (реакция — характер + `Trust.Luck`), пресса; сдвигает норму настроя и смягчает обиды; «раздевалка видит» — `Trust.RoomSees` (лидеры, письмо капитана). Пресс-конференции — `Press.cs` (после разгрома, перед матчем с лидером, о спаде; «обещал доказать» — `Career.Boasts`). Игра через боль: обострение — травма дольше, лидеры запоминают. Проверка «Доверие и пресса».
  Тренировки — `Training.cs` (`Career.Training`, только свой клуб; у ИИ множители 1): нагрузка (развитие ×0,8/×1,25 против свежести, травм и настроя), упор недели (группа характеристик ×1,45 за счёт остальных; «система» — выучка, «сыгранность» — `Career.TrainChem`, «восстановление»), индивидуальная работа (×2 одной характеристике, 6 мест); страницы `TrainingPage` (неделя, индивидуальные, молодые). Проверка «Тренировки».
  Тренеры — `Staff.cs` (`Career.Staff`: главный тренер у каждого клуба ИИ, помощник у своего): тактика, оценка игроков, работа с людьми, мотивация, гибкость; стиль — любимый форчек, риск, молодые/ветераны. Советы — взгляд тренера: игроки `Staff.View/AttrView` (ошибка по «оценке игроков», постоянная для пары тренер–игрок, плюс пристрастия, усталость и половина формы), выгода решений `Staff.Estimate` (ошибка по «тактике») и `Confidence`. Звенья — `LineOpt` (линейная модель силы клуба, мгновенный перебор): «Вариант помощника», анализ состава и ИИ.
  Тренеры ИИ — `AiCoach.cs`: стиль в настройках (снятие, темп, правила перерывов), правка звеньев перед сезоном и раз в неделю (`AiTuned`), план под соперника у гибких (в серии с игроком — по `LastUserSys`), смена системы, если полсезона не идёт. Проверка «Умный бот» (`SmartBotFixed`: те же матчи; подробно `... botfix N`, по сезонам `... bot N`).
  «Вариант помощника» (`Coach.Propose/Assess`, окно `AssistantReview`): перестановки от текущего состава по способностям без формы; показывает сыгранность (`FamGoals`), обиды по статусу и минуты молодых — решает тренер. Проверка «Нет одного верного решения»; подробно: `... HM27.Check -- game/data/hm27-data.json coach`.

## Интерфейс
- Дизайн-система «Премиум» — `Ds.cs` (выбрана в дизайн-лаборатории `ui/lab/`, `--screen=lab --dir=A|B --tab=lines|home`): тёмный лёд (`Ds.Bg`, фон-шейдер `IceBg` со свечением цвета клуба), стекло (`GlassBox` — настоящее размытие, `Ds.GlassBoxStyle`), таблетки (`Ds.Pill`), мягкие углы.
  Рейтинг OVR 50–99 из видимой КА (`Ds.Ovr`), ступени `Ds.Tier`: бронза <65, серебро 65+, золото 75+, лёд 85+; кольцо рейтинга — `Face.Ring`. Характеристики 1–20 — `Ds.Attr` (тусклый → белый → зелёный → золото), свежесть `Ds.FreshCol`, сыгранность `Ds.FamCol`.
  Лица и эмблемы в любой фигуре — `Face.Player/Logo/Glow` (без пака — инициалы и круг в цветах клуба). Рисованные элементы — `Paint`. Одно появление волной — `Ds.Reveal`.
  Шрифты: заголовки страниц — Unbounded (`Ds.Display`), текст — Onest (`Ui.Regular…Bold`), числа и таблицы — Fira Sans Extra Condensed (`Ui.Cond…`); трансляция — Sofia Sans Extra Condensed курсив (`Ds.Tv`) только для заглавных и цифр (строчная кириллица у него болгарская).
  Заголовки: страницы — шапка оболочки; разделы страницы — `Ds.Display` 20; подзаголовки и заголовки виджетов — `Ui.Semi` 13–17; узкий Fira — только числа, таблицы и плашки. Панели — радиус 14–20 (`Ui.Box` поднимает мелкие радиусы до 8), свой клуб в таблицах — свечением `Ui.Club`.
  Цвета `Ui.*` — через дизайн-систему: панели полупрозрачные (`Ui.Panel`), синяя линия (`Blue`) — нажимаемое, красный — голы, поражения, тревоги, янтарь (`Gold`) — главное; цвет клуба — свечение и акценты (`Ds.ClubBright`).
- Трансляция (направление A, только моменты) — `MatchBroadcast.cs`: табло `Scorebug` (читает подписи счёта и часов экрана матча), заставка `MatchIntro` перед трансляцией (щелчок — пропустить), полоса гола `GoalBanner` (не на скорости ×8). Снимок гола: `--screen=match --live=400 --goal=1 --frames=16`.
- Цвета в матче — `MatchColors` (`MatchViz.cs`), как на льду: хозяева в основном цвете, гости в основном или втором (только первые два цвета клуба), при похожих — белый. Свой цвет клуба — только идентичность (боковая панель, своя эмблема, свечение), не заливка шкал.
- Оболочка (`Shell.cs`): боковая панель — свой клуб, разделы (Портал, Команда, Тренировки, Календарь, Сделки, Скаутинг, Клуб, Лига), у раскрытого — его страницы; поиск, настройки, дата, «Продолжить» (цвет клуба; в день матча — янтарная, ждёт решения — красная) и «До матча». Шапка: назад/вперёд, эмблема со свечением, заголовок (Unbounded), лента 7 дней. Вкладки-таблетки — только у чужого клуба и игрока. Незаконченное — пункт «скоро».
- Портал (`HomePage`): следующий матч (эмблемы со свечением, шансы полосой в цветах клубов), главный материал с фото героя, лидеры клуба лицами (`LeadersStrip`). Карточка игрока — постер (`PlayerPage.Hero`: фото в косом срезе, рейтинг в кольце). Лицо в круге с эмблемой — `FaceDot` (в т. ч. `Article.PlayerChip`).
  Итог матча — финальное табло и три звезды с фото (`FinalBoard` в `MatchBroadcast.cs`) во всю ширину над статистикой.
- Звенья (`LinesView` + `LinesCards.cs`): по умолчанию карточки (`LineCard`: фото в кольце рейтинга, сильная сторона, роль, свежесть; связи сыгранности между партнёрами), перетаскивание карточки на карточку — обмен, из запаса (`BenchChip`) — в состав; щелчок — кандидаты рядом с карточкой, двойной — профиль. Виды: «Пятёрки», «Спецбригады», «Доска» (тактическая доска с кандидатами), «Настройки» (`--lines=cards|special|board|settings` для снимков).
- Состав (`SquadPage`): карточки по позициям (`SquadCard`) и таблица — переключатель. Календарь — сетка месяца `CalendarGrid` (список — второй вид). Экран «до матча» — левая колонка (прогноз, старт), справа вкладки «План на матч / Задания / Соперник / Концовка и правила» (страницы создаются один раз и прячутся, `Ui.Clear` их не трогает). Поиск — в шапке оболочки, результаты — слой без фокуса (`Shell.SearchBox`). Страницы «Трибуна» и «Гонка за призами» — `FansPages.cs` (`StandsPage` с графиком `FanChart` по `Career.FanTrend`, `RacesPage` по `News.Races(c, 5)` и `Career.Honors`).
- Статистика в игре — своя история с первого дня: реальный текущий сезон НХЛ нигде не показывается (`BioText.Past`), прошлые сезоны — в карьере игрока, сезон в игре — первой строкой.
- Карточка игрока — вкладки (`--tab=player:stats`): графика в `PlayerViz.cs` (паутинка против среднего игрока позиции, плитки состояния, перцентили за 60 минут).
- Новости — `News.cs` (ядро): отчёт о своём матче, «Вечер в НХЛ» (хет-трики, сухари, серии, юбилеи по реальной карьере + сезону в игре), «Неделя в НХЛ», «Цифры» (раз в две недели), «Пресса» (сюжеты из таблицы и формы). Только факты из движка, на игру не влияют.
  Письмо — статья (`Message.Tag/Lead/Facts/Players/Quote`, вёрстка `Article.cs`); новости лиги и прессы (`IsNews`) не входят в счётчик непрочитанных.
  Голоса — `Voices.cs`: журналисты карьеры (аналитик «Лёд и цифры», инсайдер, эксперт-ветеран студии «Овертайм», местный репортёр «<City> Herald», таблоид, лента) — подпись `Message.From` = «Имя, издание», аватар `Article.Avatar/Byline`; болельщики — `Career.FanMood` (результат против прогноза, серии, место против ожиданий прессы) и посты `Career.Fans` после своих матчей.
  Сюжеты — `NewsStories.cs` (partial `News`): превью своего матча с прогнозами трёх экспертов (`News.Picks`), рейтинг силы по вторникам (`News.Power`, `Career.PowerWeek`), игроки месяца и гонка за призами (`News.Races`, `Career.Honors`), призы сезона после регулярки, погони за 50 голами и 100 очками (`Career.Chases`), тренер под угрозой → ультиматум → отставка у клубов ИИ (`Career.HotSeat`, `Staff.Replace`, `AiCoach.InitTeam`; не больше одной в неделю и трёх за сезон — единственный сюжет, который меняет игру).
  Цитаты по характеру — `Quotes.cs` (личность → голос: лидер, профессионал, честолюбивый, эмоциональный, спокойный, скромный; тренеры ИИ — по стилю); первая фраза в разговоре «мало играю» — тоже. Пресс-конференции: вопрос задаёт журналист-персонаж, ответ тренера выходит в его материале (`Press.Quoted`).
  Портал (`HomePage`): главный материал с автором, следующий матч с прогнозами экспертов, лента с аватарами, «Трибуна», «Рейтинг силы», «Гонка за призами». Проверка текстов глазами: `dotnet run -c Release --project core/HM27.Check -- game/data/hm27-data.json news MIN 60`.
- Статистика клубов — `TeamStats.cs` (вкладка клуба «Статистика», Лига → «Клубы»): xG, реализация, % отражённых, PDO, «голы сверх моментов».
- Матч: события бросков хранят зону и xG (`MatchEvent.Z`, `Xg`; без вызовов генератора — исходы не меняются); `MatchViz.cs` — ожидаемые голы по ходу матча и карта бросков (точка внутри зоны — детерминированно от события).
- Снимок с раскрытым разделом боковой панели: `--open=team`; высокий снимок — запуск godot с `--resolution 1600x2600`; письмо — `--tab=inbox --arg=<id>`.

## Принципы движка
- Сила клубов «снизу вверх» (`TeamStrength.cs`, новые карьеры: `Career.BottomUp`): перед каждым матчем — из истинных характеристик игроков текущего состава при их минутах, с формой (в плей-офф — с хладнокровием), и вратаря матча. Модель «Сводки» задаёт только масштаб (разброс сил × SPREAD), не порядок; поправки «относительно базы» в этом режиме обнулены. Проверка «Таблица как в НХЛ» в HM27.Check.
- Прогноз до сезона и статус клуба (`Pundits`, пять ступеней `Band`) — `TeamStrength.Estimate(d, t, missed)`: смесь здорового состава и состава без травмированных с долей пропуска по сроку травм (дни / 180), не «выбыл на весь сезон».
- Старые сохранения (BottomUp = false): состав по умолчанию даёт ровно силу модели, эффект решений — отличие от базы (`BaseOff`, `BaseDef`, `BaseGsax` в `Career`).
- Случайность детерминирована: `Random(Seed * 1_000_003 ^ gameId)`. Не использовать `HashCode` (он случаен между процессами).
- 3Д не решает исход: только показывает то, что посчитал движок (ТЗ 7.4).

## Локальная проверка в рабочем окружении Claude
- NuGet.org недоступен: пакеты Godot берутся из локального источника (`~/.nuget/NuGet/NuGet.Config` → `GodotSharp/Tools/nupkgs` из папки Godot). В репозитории `nuget.config` нет — в CI используется nuget.org.
- Снимки экранов без монитора: Xvfb + программный Vulkan (llvmpipe). Скрипт `tools/shot.sh` (нужны `xvfb`, `mesa-vulkan-drivers`).
  Параметры игры для снимков: `-- --screen=menu|clubs|hub|match --tab=lines|table|stats|calendar|playoffs --days=N --sim=1 --played=1 --shot=путь.png`.
- Экспорт под Windows/macOS локально не работает (нужны runtime-пакеты с nuget.org) — сборки делает GitHub Actions (`.github/workflows/build.yml`), результат — релиз `dev`.
